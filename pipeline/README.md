# 콘텐츠 파이프라인

경로 파일 하나를 받아서 앱이 읽는 경로 패키지(JSON)를 만든다. 경로 주변의 장소를 찾고, 장소마다 짧은 이야기와 긴 이야기, 퀴즈를 Claude에게 쓰게 한 뒤, 근거 문서와 대조해 통과한 것만 패키지에 넣는다.

## 지금 상태

- 테스트 51개가 통과한다. 위키백과, TourAPI, Claude를 모두 대역으로 바꿔서 돌리므로 네트워크와 키가 필요 없다.
- **실제 서비스로는 한 번도 돌려 보지 못했다.** 작성한 환경에서 위키백과와 공공데이터포털에 접근할 수 없었고 API 키도 없었다. 첫 실행에서 응답 형식이 예상과 다르면 `sources.py`를 고쳐야 한다.
- TourAPI 부분은 공개된 매개변수 표를 보고 썼다. 키를 발급받아 처음 돌릴 때 확인이 필요하다.
- Claude 호출은 `anthropic` SDK 2.8.0이 요청을 받아 서버로 보내는 데까지만 확인했다(가짜 키라 인증 오류로 끝났다). 모델이 실제로 어떤 글을 쓰는지는 보지 못했다.
- 앱에 들어 있는 서울 → 강릉 패키지는 이 파이프라인이 만든 것이 아니다. 손으로 쓴 것이고, `check` 명령은 통과한다.
- 파이프라인이 쓴 패키지를 앱이 읽는지는 파일 하나로 양쪽을 묶어 확인한다. `tests/test_package.py`는 `app/src/test/resources/pipeline-package.json`이 지금 파이프라인이 쓰는 내용과 같은지 보고, 앱의 `RoutePackageParserTest`는 그 파일을 앱의 파서로 읽는다. 패키지 형식을 일부러 바꿨으면 환경 변수 `GILDONGMU_UPDATE_FIXTURES=1`을 주고 테스트를 돌려 파일을 다시 쓴 다음 앱 테스트를 돌린다. 이 파일의 이야기와 퀴즈는 테스트용으로 넣은 글이다.

## 설치

Python 3.10 이상이 필요하다.

```
cd pipeline
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"
```

## 환경 변수

| 변수 | 필요한 때 | 내용 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | `build` | Claude API 키 |
| `TOURAPI_KEY` | 선택 | 공공데이터포털에서 발급받은 "한국관광공사 국문 관광정보 서비스" 키의 Decoding 값. 없으면 위키백과만 쓴다 |
| `GILDONGMU_CONTACT` | `candidates`, `build` (권장) | 위키백과 요청에 붙일 연락처(메일 주소나 URL). 위키미디어는 자동화된 요청에 연락처를 요구한다. 비워 두어도 실행은 된다 |
| `GILDONGMU_MODEL` | 선택 | 이야기를 쓸 Claude 모델 ID. 기본값은 `claude-opus-5-5`이고, `--model`로도 바꿀 수 있다 |

PowerShell에서는 `$env:ANTHROPIC_API_KEY = "..."`, 명령 프롬프트에서는 `set ANTHROPIC_API_KEY=...`로 넣는다. 키를 파일에 적어 저장소에 올리지 않는다.

## 사용법

먼저 모델을 부르지 않고 어떤 장소가 잡히는지 본다. 키가 필요 없다.

```
python -m gildongmu_pipeline candidates routes/seoul-gangneung.route.json
```

한 줄에 후보 하나씩, 경로상 위치와 도로에서 떨어진 거리, 근거 문서 길이, 제목, 출처가 나온다. 맨 앞에 `*`가 붙은 곳이 이야기를 쓸 곳이다.

패키지를 만든다.

```
python -m gildongmu_pipeline build routes/seoul-gangneung.route.json --out out/seoul-gangneung.json
```

만든 패키지나 손으로 고친 패키지를 앱과 같은 규칙으로 검사한다.

```
python -m gildongmu_pipeline check out/seoul-gangneung.json
```

`candidates`와 `build`의 선택 사항:

| 옵션 | 기본값 | 뜻 |
| --- | --- | --- |
| `--max-pois` | 8 | 이야기를 쓸 장소 수 |
| `--min-gap-km` | 15 | 장소 사이의 최소 간격. 너무 가까우면 이야기가 겹친다 |
| `--every-km` | 8 | 경로를 따라 장소를 찾는 간격 |
| `--no-tourapi` | | `TOURAPI_KEY`가 있어도 위키백과만 쓴다 |
| `--model` | `claude-opus-5-5` | `build`에서 쓸 모델 |

## 동작 순서

1. 경로선을 8km마다 찍고, 각 지점 반경 10km 안에서 좌표가 있는 한국어 위키백과 문서를 찾는다. 키가 있으면 TourAPI의 관광지와 문화시설도 찾는다.
2. 도로에서 8km 넘게 떨어진 곳을 뺀다. 나들목, 역, 학교, 행정구역, 회사처럼 가족이 흥미를 느끼기 어려운 제목도 뺀다.
3. 근거 문서를 가져온다. 위키백과는 문서의 도입부, TourAPI는 개요다. 200자가 안 되면 쓰지 않는다.
4. 근거 문서가 길고 도로에 가까운 순으로, 서로 15km 이상 떨어지게 고른다. TourAPI에서 온 장소는 조금 우대한다.
5. 장소마다 근거 문서를 Claude에 주고 이야기 두 편과 퀴즈를 정해진 JSON 형식으로 받는다.
6. 받은 글을 검사한다. 통과하지 못하면 이유를 알려 주고 한 번 더 쓰게 한다. 그래도 안 되거나 모델이 이야깃거리가 아니라고 판단하면, 같은 구간의 다음 후보를 두 곳까지 시도한다.
7. 패키지를 조립하고, 앱이 읽을 때와 같은 규칙으로 검사한 뒤 저장한다.

Claude 호출은 장소마다 한두 번이다. 기본 설정에서 보통 8~16번이고, 후보가 계속 반려되면 최대 48번까지 간다.

## 검사

모델이 쓴 글은 아래를 통과해야 패키지에 들어간다.

- 이야기에 나오는 두 자리 이상의 숫자는 근거 문서에 있어야 한다.
- 퀴즈마다 정답의 근거가 되는 문장(`evidence`)이 근거 문서에 글자 그대로 있어야 하고, 정답이 근거 문서에 나와야 한다.
- 보기가 있는 문제는 보기 가운데 정확히 하나만 정답이어야 한다.
- 괄호, 한자, 기호처럼 음성 합성이 제대로 읽지 못하는 문자가 없어야 한다.
- "지금 지나는", "여기는", "이제"처럼 차가 그 자리에 있어야 맞는 말로 시작하면 안 된다. 호스트는 장소에 닿기 전이나 휴게소에서 쉬는 동안에도 이야기를 들려준다.
- 읽는 시간이 짧은 버전은 9~22초, 긴 버전은 28~60초여야 한다. 시간은 앱과 같은 계산식으로 추정한다.

**이 검사가 못 잡는 것이 있다.** 숫자와 인용문만 대조하므로, 사람 이름이나 사건의 앞뒤 관계처럼 숫자가 아닌 사실이 근거와 다른 경우는 통과한다. 아이들에게 들려주기 전에 사람이 근거 문서와 함께 읽어 봐야 한다. 패키지의 `sources`와 퀴즈의 `evidence`가 그때 쓰라고 남긴 것이다.

## 경로 파일

`routes/seoul-gangneung.route.json`이 예시다. 앱에 들어 있는 패키지에서 장소만 뺀 것과 같다. 형식은 아래와 같다(경로선과 휴게소는 앞부분만 보였다).

```
{
  "id": "seoul-gangneung",
  "title": "서울 → 강릉",
  "origin": { "name": "서울 양재", "lat": 37.466, "lon": 127.04 },
  "destination": { "name": "강릉 경포해변", "lat": 37.805, "lon": 128.908 },
  "polyline": [[37.466, 127.04], [37.3755, 127.104]],
  "stops": [ { "id": "deokpyeong", "name": "덕평자연휴게소", "lat": 37.244, "lon": 127.36, "charger": true } ],
  "generalQuiz": [],
  "geometryNote": "좌표에 관해 남길 말",
  "spots": [ { "id": "food-chodang", "category": "food", "name": "초당두부마을", "area": "강릉", "lat": 37.7878, "lon": 128.9149,
               "reason": "간수 대신 바닷물로 만드는 초당두부의 고장이에요.", "near": "destination",
               "sources": [ { "title": "위키백과: 초당두부", "url": "https://ko.wikipedia.org/wiki/초당두부" } ] } ],
  "funQuiz": [ { "id": "riddle-age", "kind": "riddle", "prompt": "아무리 먹어도 배가 부르지 않은 것은 무엇일까요?", "answers": ["나이"], "explanation": "…" } ]
}
```

`polyline`은 `[위도, 경도]`의 목록이다. 예시 파일의 경로선은 나들목을 직선으로 이은 근사값이라 실제 도로와 어긋난다. 실제 서비스에서는 내비가 주는 경로를 넣어야 한다.

`stops`와 `generalQuiz`는 파이프라인이 찾거나 쓰지 않고, 경로 파일에 적힌 대로 패키지에 옮긴다. 휴게소와 충전기 데이터를 가져오는 부분은 만들지 않았다.

`spots`(먹거리·볼거리)와 `funQuiz`(수수께끼·넌센스 퀴즈)도 지금은 손으로 써서 경로 파일에 두고, 그대로 패키지에 옮긴다. 둘 다 없어도 된다. `spots`의 `category`는 `food`, `sight`, `cafe` 가운데 하나이고, `near`는 휴게소 ID나 `destination`이며 생략할 수 있다. `reason`은 왜 가 볼 만한지 말하는 한 문장이고, 이야기와 같은 규칙(읽을 수 있는 문자만, 그 자리에 있어야 맞는 말로 시작하지 않기)으로 검사한다. 곳마다 출처가 하나 이상 있어야 한다. `funQuiz`는 퀴즈 형식에 `kind`(`riddle`이나 `nonsense`)를 더한 것이고, 사실이 아니라 말장난이라 출처가 필요 없다. TourAPI에서 먹거리·볼거리를 가져오는 부분은 아직 없다.

## 만든 패키지를 앱에 넣기

`mock` 빌드는 `app/src/main/assets/routes/seoul-gangneung.json`과 데모 대본 `app/src/mock/assets/scenarios/seoul-gangneung-demo.json`을 읽는다. 파일 이름은 `MockPlatform.kt`에 적혀 있다.

데모 대본은 손으로 쓴 패키지에 맞춰져 있다. 새로 만든 패키지로 바꾸면 두 가지를 손봐야 한다.

- 파이프라인은 장소 ID를 `poi-01`, `poi-02`처럼 붙인다. 대본의 `onlyPois`는 손으로 쓴 패키지의 ID(`yeongneung` 등)를 가리키므로, 새 ID로 바꾸거나 항목을 지워서 모든 장소를 쓰게 한다. ID가 맞지 않으면 앱은 데모를 시작하지 않고, 패널과 Logcat(`Gildongmu` 태그)에 어떤 ID가 없는지 알린다.
- 대본의 `legs`와 `events`는 손으로 쓴 패키지의 장소 위치에 맞춰 속도를 조절해 둔 것이다. 장소 위치가 달라지면 이야기가 잘리거나 겹칠 수 있으니 구간별 `timeScale`을 다시 맞춘다. `DemoDriveTest`를 돌리면 대본이 출력되어 결과를 바로 볼 수 있다.

## 출처와 이용 조건

- 위키백과 본문은 CC BY-SA 4.0으로 배포된다. 그 본문을 근거로 쓴 이야기에도 출처 표시와 같은 조건 유지가 요구될 수 있어서, 패키지에 문서 제목과 주소를 남긴다. 서비스로 내놓기 전에 조건을 확인해야 한다. 이 부분은 법률 검토를 거치지 않았다.
- TourAPI 데이터의 이용 조건은 공공데이터포털의 해당 데이터 페이지(https://www.data.go.kr/data/15101578/openapi.do)에서 확인한다.
